网络是后端与前端共同的隐形依赖：同一段代码在办公网、云内网、跨境链路上的表现能差十倍，而「网络有问题」这四个字几乎无法直接排查。本教程把 TCP/IP 栈拆成可验证的分层事实——从 MAC 与 IP 各管哪一段、TCP 的队列与 TIME_WAIT、拥塞算法到底在决定什么，一直到 QUIC 为什么搬进用户态，全程以 Linux 命令与抓包输出为证据，最终建立一套「看数据判断是哪一层」的排障语言。

## 前置教程

- [Linux 教程](../linux/)：`ip`/`ss`/`tcpdump`/`sysctl` 是本教程的主要观测工具，需要熟悉命令行与进程、服务的基本操作

## 你将学到

- 用分层语言描述故障：判断一个问题属于二层、三层、传输层还是应用层
- 读写 CIDR、划分子网、查路由表与邻居表，理解 IP 端到端与 MAC 逐跳的分工
- 讲清三次握手与四次挥手各自在确认什么，并独立处理 TIME_WAIT 堆积与连接队列溢出
- 从 `ss -ti` 与抓包里读出 rtt、rto、cwnd、retrans，区分流量控制与拥塞控制
- 理解 CUBIC 与 BBR 的信号差异，知道换算法什么时候有效、什么时候是白忙
- 判断 UDP 与 QUIC 的适用边界：0-RTT、连接迁移、按流恢复各自的收益与代价
