**本章目标：**

- 会用「重叠子问题 + 最优子结构」两道门槛判断一个问题能不能上 DP
- 掌握三段式建模（定义状态 → 写转移 → 定初值与顺序），能写出一维与二维状态
- 熟悉背包、LIS、LCS 三类经典模型，并能用滚动数组和状态压缩把空间压下来

## 11.1 两道门槛：重叠子问题与最优子结构

动态规划（DP）不是算法，而是一种**记账方式**：把子问题的答案存下来，保证每个子问题只算一次。它比 [第 10 章 · 递归与分治](./10-recursion-divide/) 的记忆化多做的，只是「把依赖顺序排好、按序填表」。

能用 DP 的问题要同时过两道门槛：

```text
重叠子问题：自顶向下展开时，同一批参数被反复求到（斐波那契、背包的 (前 i 件, 容量 c)）
最优子结构：大问题的最优解，能由若干子问题的最优解组合出来
```

第二道门槛最容易想当然。**最长路径就不满足最优子结构**：从 A 到 D 的最长路径经过 B，但「A 到 B 的最长路径」可能已经把 D 用过了，接不上后半段——子问题的最优和整体最优的约束不一致。最短路径则满足：最短路上的任何一段，本身也是最短路。

判断能不能写 DP，实操上只问一句：**最后一个决策是什么？** 能把它枚举清楚（选/不选第 i 件物品、最后一步跨 1 级还是 2 级、LCS 的最后两个字符配不配对），就有转移；说不清就没有。

分治与 DP 的分界线：分治的子问题互不重叠（归并的两半各算一次就结束），DP 的子问题彼此重叠、总数呈多项式。两条思路都可行时看子问题数：不重叠走分治，重叠走 DP 或记忆化。

## 11.2 从递归到自底向上

爬楼梯：每次上 1 级或 2 级，到第 n 级有几种走法。先写递归版：`f(n) = f(n-1) + f(n-2)`，基线 `f(1)=1, f(2)=2`。把「依赖更小状态」这句话变成循环，就得到三段式：

```text
1. 定义状态：dp[i] = 走到第 i 级的方案数（一句话说不清就别往下写）
2. 写转移：  最后一步要么跨 1 级要么跨 2 级 → dp[i] = dp[i-1] + dp[i-2]
3. 定初值与顺序：dp[1]=1、dp[2]=2；转移只看更小的 i，所以 i 从小到大填表
```

```python
def climb_stairs(n):
    if n <= 2: return n
    prev, cur = 1, 2                    # 只留两个变量：dp 表退化成了滚动值
    for _ in range(3, n + 1):
        prev, cur = cur, prev + cur
    return cur
```

自顶向下（记忆化）和自底向上（填表）算的是同一张依赖图，差别在工程属性：填表**没有栈深风险**、能顺手做空间压缩、顺序自己控制；记忆化**只算访问到的状态**，状态转移不规则（比如搜索式 DP）时更省。写不出转移时，退回记忆化版本把重复调用打印出来，是最快的建模路径。

## 11.3 状态设计：一维与二维

状态定义决定一切。最常见的两类是「前缀型一维」和「网格/双序列型二维」。

打家劫舍（一维，房子不能偷相邻的）：最后一个决策是「偷不偷第 i 家」。

```python
def rob(money):
    prev2, prev1 = 0, 0                 # dp[i-2] 与 dp[i-1]
    for x in money:
        prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1
```

最小路径和（二维，只能往下或往右）：状态带两个下标，`dp[i][j]` 是到格子 `(i, j)` 的最小累计和。

```python
from math import inf

def min_path_sum(grid):
    rows, cols = len(grid), len(grid[0])
    dp = [[0] * cols for _ in range(rows)]      # 每行必须是独立列表
    dp[0][0] = grid[0][0]
    for i in range(rows):
        for j in range(cols):
            if i == j == 0:
                continue
            from_up = dp[i - 1][j] if i else inf        # 越界的来源设成 +inf
            from_left = dp[i][j - 1] if j else inf
            dp[i][j] = min(from_up, from_left) + grid[i][j]
    return dp[rows - 1][cols - 1]
```

二维表的第一杀手是这一行：

```text
错误写法  dp = [[0] * cols] * rows
          → rows 行是同一个列表的别名，改 dp[0][0] 会让 dp[1][0]、dp[2][0] 一起变
正确写法  dp = [[0] * cols for _ in range(rows)]
          → 每行独立创建；只有一维表 [0] * n 才是安全的（整数不可变）
```

:::caution[状态要多带一维信息的时候，别硬推]
「必须选中最后一家」「恰好装满」这类约束，靠转移判不住，就把约束写进状态本身：`dp[i][k]`，k 表示是否已选。多一维通常只让空间乘一个小常数，却能把「写不出转移」变成「写得出来」。
:::

## 11.4 背包问题的三种变形

背包是 DP 的 Hello World：`dp[c]` = 容量 c 时能获得的最大价值。三种变形只差**遍历方向**和**件数处理**。

```python
def knapsack_01(items, cap):
    """items = [(重量, 价值), ...]，每件最多选一次"""
    dp = [0] * (cap + 1)
    for w, v in items:
        for c in range(cap, w - 1, -1):        # 倒序：dp[c-w] 还是上一轮的，一件只用一次
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]

def knapsack_full(items, cap):
    """每件可以选无限次"""
    dp = [0] * (cap + 1)
    for w, v in items:
        for c in range(w, cap + 1):            # 正序：本轮更新过的 dp[c-w] 还能再用
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]

def knapsack_bounded(items, cap):
    """items = [(重量, 价值, 件数), ...]，多重背包：按二进制拆成 01 背包"""
    parts = []
    for w, v, cnt in items:
        k = 1
        while cnt > 0:                         # 拆成 1、2、4… 份，能凑出任意件数
            take = min(k, cnt)
            parts.append((w * take, v * take))
            cnt, k = cnt - take, k * 2
    return knapsack_01(parts, cap)
```

计数变形把 `max` 换成加法，且**循环层的顺序决定「组合」还是「排列」**：

```python
def coin_change_ways(coins, amount):
    dp = [0] * (amount + 1)
    dp[0] = 1                                  # 金额 0：一种（什么都不选）
    for c in coins:                            # 硬币在外层 → 组合数，不看顺序
        for a in range(c, amount + 1):
            dp[a] += dp[a - c]
    return dp[amount]
```

:::danger[滚动数组的方向是「由依赖顺序」决定的，不是口诀]
01 背包倒序、完全背包正序，本质都是同一个要求：**写 `dp[c]` 时，`dp[c - w]` 必须是上一件物品那一步的值（倒序）或本件物品已更新后的值（正序）**。「一维就倒序」这类口诀换成「求方案数」或带第二维的状态立刻失效。
:::

## 11.5 最长递增子序列与最长公共子序列

LIS 的状态是「以 i 结尾」而不是「前 i 个」——这个差别是全局最优和可转移的关键：`dp[i]` 必须以 `a[i]` 收尾，才能保证答案可以再接后续元素。

```python
def lis_length(a):
    dp = [1] * len(a)                          # 每个元素自己就是长度 1 的子序列
    for i in range(len(a)):
        for j in range(i):
            if a[j] < a[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp, default=0)
```

O(n²)。要降到 O(n log n)，就维护「长度为 k 的递增子序列的最小结尾」，用二分找插入位置（[第 9 章 · 查找与二分](./09-searching/) 的 `bisect_left` 直接可用）——注意这个数组是贪心维护的辅助量，它本身不是答案序列。

LCS 是标准二维：多出来的那一行一列代表「空串」基线，避免所有下标特判。

```python
def lcs_length(s, t):
    rows, cols = len(s) + 1, len(t) + 1
    dp = [[0] * cols for _ in range(rows)]
    for i in range(1, rows):
        for j in range(1, cols):
            if s[i - 1] == t[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1        # 两个末尾字符配对
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])   # 丢掉其中一个的末尾
    return dp[rows - 1][cols - 1]
```

## 11.6 滚动数组与状态压缩

如果填表时只会用到上一行，就把二维降成两行甚至一行：

```python
def lcs_rolling(s, t):
    prev = [0] * (len(t) + 1)
    for cs in s:
        cur = [0] * (len(t) + 1)
        for j, ct in enumerate(t, start=1):
            cur[j] = prev[j - 1] + 1 if cs == ct else max(prev[j], cur[j - 1])
        prev = cur                             # 整行换掉，旧行不再需要
    return prev[len(t)]
```

空间从 O(n·m) 降到 O(m)。想再降成**一维原地滚动**，就必须处理「左上角 `prev[j-1]` 已经被本轮覆盖」的问题——用一个临时变量存对角线值，或者干脆保留两行。这和 11.4 里倒序遍历是同一件事的两种解法：**先看清依赖方向，再决定能不能原地覆盖**。

状态压缩是另一条路：n 很小（不大于 20）但需要「哪些元素已用过」这种集合信息时，把集合编码成一个整数的二进制位。旅行商是标准例子，`dp[mask][i]` = 已访问集合为 mask、当前停在 i 的最小代价：

```python
def tsp(cost):
    from math import inf
    n = len(cost)
    full = 1 << n
    dp = [[inf] * n for _ in range(full)]
    dp[1][0] = 0                                   # 从 0 出发，已访问集合只有 {0}
    for mask in range(full):
        for i in range(n):
            if not (mask >> i) & 1 or dp[mask][i] == inf: continue
            for j in range(n):
                if (mask >> j) & 1: continue       # j 已经去过
                nxt = mask | (1 << j)
                dp[nxt][j] = min(dp[nxt][j], dp[mask][i] + cost[i][j])
    return min(dp[full - 1][i] + cost[i][0] for i in range(1, n))
```

复杂度 O(2ⁿ · n²)，把暴力枚举的 O(n!) 压下来一大截，但状态数仍随 n 指数增长：n = 20 时 `2^20 × 20 ≈ 2×10⁷` 个状态已经接近内存和时间的上限。**看到「n 不超过 20」就想到状压，n 到 40 就该换思路**（meet in the middle 或搜索剪枝，见 [第 12 章 · 贪心、回溯与搜索](./12-greedy-backtracking/)）。

## 11.7 综合练习：DP 还是贪心

贪心每一步只取当前最优，DP 保留所有可能的代价。两者的边界很干脆：**贪心要成立，必须证明「局部最优能扩展成全局最优」**（交换论证，见第 12 章）；一旦存在「现在少拿一点、后面更划算」的取舍，就必须 DP。

```python
def coins_greedy(coins, amount):
    used = []
    for c in sorted(coins, reverse=True):          # 每次拿面值最大的
        while amount >= c:
            used.append(c)
            amount -= c
    return used if amount == 0 else None

def coins_dp(coins, amount):
    INF = float("inf")
    dp = [INF] * (amount + 1)
    dp[0] = 0                                      # 金额 0 不需要任何硬币
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)   # 最后一个用的硬币是 c
    return dp[amount] if dp[amount] < INF else -1

for coins, amount in ([1, 3, 4], 6), ([1, 5, 10, 25], 30):
    print(coins, amount, "贪心 =", coins_greedy(coins, amount),
          "DP =", coins_dp(coins, amount))
```

```text
$ python coins.py
[1, 3, 4] 6 贪心 = [4, 1, 1] DP = 2
[1, 5, 10, 25] 30 贪心 = [25, 5] DP = 2
```

第一行是经典反例：面值 `[1,3,4]` 凑 6，贪心给出 3 枚（4+1+1），最优是 2 枚（3+3）。第二行是**真实硬币体系**——贪心恰好正确，但那是面额设计出来的性质，不是普适规律。背包同理：按「单位价值」排序的贪心在**分数背包**上成立（可以切一半），在 01 背包上会因装不满剩余容量而错。

:::tip[三条自查]
① 有没有「先让一步、后面翻盘」的构造？有 → DP。② 贪心的答案和 DP 的答案在随机小规模数据上对拍一致吗？先写 DP 当基准，再试贪心。③ 状态能不能压？只会用到上一行就滚动，集合小就把集合塞进整数位。
:::

## 本章小结

- DP 的两道门槛是重叠子问题与最优子结构；建模只问一句话「最后一个决策是什么」，说不清就没有转移
- 三段式：定义状态（一句话说清 dp 的含义）→ 写转移 → 定初值与遍历顺序；填表版没有栈深风险，记忆化版只算访问到的状态
- 背包三种变形只差遍历方向与件数拆分：01 倒序、完全正序、多重按二进制拆；方向由依赖顺序决定，不能背口诀；二维表务必逐行独立创建
- 贪心只有在「局部最优可扩展为全局最优」且能证明时才等价于 DP，硬币 `[1,3,4]` 凑 6 就是反例；空间不够时先试滚动数组，再考虑把集合压进二进制位
