## 功能地图

| 模块 | 作用 | 主要使用角色 |
| --- | --- | --- |
| 表单设计 | 字段、校验、联动 | 业务人员 |
| 流程设计 | 审批、条件、自动化 | 业务人员 |
| 页面设计 | 列表、详情、仪表盘 | 公民开发者 |
| 数据模型 | 表、关系、索引 | 公民开发者 |
| 权限 | 角色、数据范围 | IT/管理员 |
| 集成 | API、Webhook、连接器 | 专业开发 |

## 核心功能

### 拖拽表单

用字段组件拼表单，配置校验、联动和默认值。

### 流程编排

配置审批节点、条件分支、自动动作和消息通知。

### 数据管理

自动生成列表、筛选、导入导出和详情页。

### 权限控制

按角色、部门、数据范围控制应用和记录访问。

### 集成扩展

通过 API、Webhook 或自定义代码连接外部系统。

## 核心业务流程

### 应用搭建到发布

- **触发条件**：部门需要一个登记或审批工具
- **参与角色**：业务人员、IT
- **流程步骤**：
  1. 创建应用
  2. 设计表单
  3. 配置流程
  4. 设置权限
  5. 测试
  6. 发布
- **输入 / 输出**：输入业务需求，输出可访问的应用
- **异常与分支**：涉及敏感数据需 IT 审核；复杂逻辑转专业开发

### 变更与版本

- **触发条件**：业务规则调整
- **参与角色**：应用负责人、IT
- **流程步骤**：
  1. 修改配置
  2. 影响评估
  3. 测试
  4. 发布新版本
  5. 回滚预案
- **输入 / 输出**：输入变更内容，输出新版本与变更记录
- **异常与分支**：变更影响线上流程时先在测试环境验证

### 权限配置

- **触发条件**：新员工或组织调整
- **参与角色**：管理员、业务负责人
- **流程步骤**：
  1. 选择角色
  2. 配置数据范围
  3. 分配用户
  4. 生效
  5. 审计
- **输入 / 输出**：输入人员与角色，输出访问权限
- **异常与分支**：越权申请需审批；离职自动回收

## 单据与状态

| 单据 | 状态 | 触发动作 | 下一步 |
| --- | --- | --- | --- |
| 应用 | 草稿/测试中/已发布/已下线 | 发布、下线 | 版本 |
| 表单 | 设计中/已发布 | 发布 | 数据记录 |
| 流程 | 草稿/已启用/已停用 | 启用 | 待办 |
| 权限申请 | 待审批/已通过/已拒绝 | 审批 | 权限 |

## 业务规则

- 涉及个人敏感信息的应用必须经 IT 审核
- 应用发布前必须有测试记录
- 权限按最小必要原则分配
- 关键应用变更保留回滚版本
- 低代码应用要纳入统一运维和审计
