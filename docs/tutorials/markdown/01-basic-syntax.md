# 第 1 章 · Markdown 基础语法

**本章目标：**

- 理解 Markdown 的设计哲学
- 掌握标题、段落、强调、列表、引用等核心语法
- 能独立写出一篇结构清晰的笔记

## 1.1 Markdown 是什么

Markdown 是一种**轻量级标记语言（Lightweight Markup Language）**，由 John Gruber 在 2004 年设计。它的核心理念：

> 让作者用纯文本写作，同时通过简单符号表达格式——**专注内容，而非排版**。

对比两种写法：

```text
Word 思维：选中文字 → 点加粗按钮 → 设置字体字号
Markdown 思维：**直接打两个星号**，完事
```

Markdown 文件就是 `.md` 后缀的纯文本，任何编辑器都能打开，永不过时、永不锁定。

::: tip 渲染的概念
你写的 `# 标题` 是"源码"，阅读时看到的漂亮标题是"渲染结果"。GitHub、掘金、本站（VitePress）等平台都会自动渲染 Markdown。
:::

## 1.2 标题

用 `#` 号表示标题，数量代表层级（1~6 级）：

```markdown
# 一级标题（文章主标题）
## 二级标题（章节）
### 三级标题（小节）
#### 四级标题
```

::: warning 使用规范
- `#` 与文字之间**必须有空格**：`#标题` 是无效写法
- 一篇文章只用一个一级标题
- **不要跳级**：`##` 之后直接用 `####` 会让文档结构混乱
:::

## 1.3 段落与换行

Markdown 中，**空行**是段落的分隔符：

```markdown
这是第一段。

这是第二段。中间的空行让它们成为两个段落。
```

段内强制换行有两种方式：行尾加**两个空格**，或使用 `<br>` 标签。不同平台对单换行的处理不一致（有的合并为一段，有的保留），写跨平台文档时注意用空行分段。

## 1.4 强调

```markdown
*斜体*        → 斜体
**加粗**      → 加粗
***斜体加粗*** → 斜体加粗
~~删除线~~    → 删除线（GFM 扩展）
```

实际效果示例：这是一个*斜体词*，这是一个**加粗词**，这是一个~~过时的说法~~。

::: tip 加粗的使用度
一整段全加粗等于没加粗。加粗应该像荧光笔——只画真正的重点句。
:::

## 1.5 列表

### 无序列表（Unordered List）

用 `-`、`*` 或 `+` 开头（推荐统一用 `-`）：

```markdown
- 前端
- 后端
- 数据库
```

效果：

- 前端
- 后端
- 数据库

### 有序列表（Ordered List）

数字加点，渲染时自动重新编号（源码数字写错也没关系）：

```markdown
1. 安装 Node.js
2. 创建项目
3. 启动开发服务器
```

### 嵌套列表

子项**缩进两个空格**（或一个 Tab）：

```markdown
- 编程语言
  - JavaScript
  - Python
- 工具
  - Git
  - Docker
```

## 1.6 引用

用 `>` 开头，常用于引用原文、补充说明：

```markdown
> 这是一段引用。
>
> 引用也可以多段。
```

效果：

> 这是一段引用。
>
> 引用也可以多段。

引用支持嵌套（`>>`）和内部使用其他语法（列表、加粗等）。

## 1.7 分隔线

三个及以上的 `-` 或 `*` 独占一行：

```markdown
---
```

::: warning 注意
`---` 单独使用是分隔线；如果它紧跟在文字下一行，会被解析成**二级标题**（setext 语法）。想让文字变成标题加空行，想画分隔线也加空行。
:::

## 本章小结

- 专注内容，符号表达格式；`.md` 纯文本永不过时
- 标题 `#` 带空格、不跳级、h1 唯一
- 空行分段；强调像荧光笔只画重点
- 有序/无序/嵌套列表与引用是笔记的骨架；`---` 独占一行才是分隔线
