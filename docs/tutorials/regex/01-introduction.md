# 第 1 章 · 初识正则表达式

**本章目标：**

- 理解正则表达式解决什么问题
- 建立"匹配思维"：从"找一个字符"到"描述一类字符串"
- 跑通第一个正则测试

## 1.1 正则表达式是什么

正则表达式（Regular Expression，简称 regex 或 regexp）是用**一个字符串来描述一类字符串**的模式语言。

两个典型场景：

```text
校验：这个字符串是合法手机号吗？
查找/替换：把文档里所有 2024-01-01 格式的日期换成 2024/01/01
```

不用正则要写十几行 if 判断与循环；用正则一行搞定：

```text
^1[3-9]\d{9}$
```

这行"天书"的含义是：以 1 开头、第二位是 3~9、后面恰好跟 9 位数字、到此结束——这就是手机号的模式。

::: tip 一个心态提醒
正则的难点从来不是"背符号"，而是**换一种思维**：从"程序怎么处理字符"换成"目标字符串长什么样"。本章就是帮你完成这个思维切换。
:::

## 1.2 匹配思维三步法

拿到需求后按三步拆解：

```text
第一步：这个字符串由哪几"段"组成？
第二步：每一段是什么"类型"（固定字符？数字？任意字符？）
第三步：每一段出现"几次"（一次？至少一次？恰好 11 次？）
```

以"校验用户名（2~8 个字母或数字）"为例：

```text
第一段：全是字母或数字    → 字符类
出现次数：2 到 8 次       → 量词
整串从开头到结尾          → 锚点
```

组合成模式：`^[a-zA-Z0-9]{2,8}$` —— 语法后面几章逐个讲，但**拆解思路现在就能开始练**。

## 1.3 你的第一个正则测试

推荐在线工具 [regex101.com](https://regex101.com/)（可视化解释每个符号，强烈建议边学边练），或在浏览器控制台测试：

```js
const re = /hello/
re.test('hello world')  // true —— 包含 hello
re.test('hi there')     // false —— 不包含
```

正则的两种常见书写形式：

```js
// 字面量（推荐，简洁）
const re1 = /pattern/flags

// 构造函数（模式来自变量时使用）
const re2 = new RegExp('pattern', 'flags')
```

## 1.4 最简单的匹配规则

在讲元字符之前，先记住两条基本规则：

**规则一：普通字符精确匹配自身**

```js
/cat/.test('I have a cat')  // true
/cat/.test('I have a dog')  // false
```

**规则二：正则默认区分大小写**

```js
/cat/.test('Cat')      // false
/cat/i.test('Cat')     // true —— i 标志表示忽略大小写
```

常用标志（flags）一览：

| 标志 | 含义 |
| --- | --- |
| `i` | 忽略大小写（ignore case） |
| `g` | 全局匹配，找出所有（global） |
| `m` | 多行模式，`^`/`$` 匹配每行的首尾（multiline） |

## 1.5 认识元字符

正则中有一批**有特殊含义的字符**，称为元字符（metacharacter），它们是接下来两章的主角：

```text
.  ^  $  *  +  ?  {  }  [  ]  \  |  (  )
```

::: warning 先建立印象
元字符意味着"这些符号不能按字面意思理解"。想匹配元字符本身需要转义（如匹配真实的 `.` 要写 `\.`），第 2 章详解。
:::

## 本章小结

- 正则 = 用一个字符串描述一类字符串；难点是匹配思维不是背符号
- 三步法：拆结构 → 定类型 → 数次数
- regex101 边学边练；标志 `i` 忽略大小写、`g` 全局
- 元字符不能按字面理解，转义用 `\`
