# 第 4 章 · 常用场景实战

**本章目标：**

- 综合运用前章知识，独立完成高频文本任务
- 掌握校验、提取、替换三类场景的标准套路
- 理解"可读性换功能"的取舍

::: tip 本章用法
每个案例先自己尝试写，再对照答案。所有示例基于 JavaScript，可在浏览器控制台直接运行。
:::

## 4.1 校验类：整串匹配

校验的黄金公式：**`^` + 模式 + `$`**。

### 手机号（中国大陆）

```js
const phoneRe = /^1[3-9]\d{9}$/
phoneRe.test('13812345678')  // true
phoneRe.test('12345678901')  // false —— 第二位限 3~9
```

### 邮箱（简化实用版）

```js
const emailRe = /^[\w.+-]+@[\w-]+(\.[\w-]+)+$/
emailRe.test('dev@example.com')   // true
emailRe.test('a@b')               // false —— 至少一个点后缀
```

::: info 严格邮箱正则
RFC 5322 标准的完整邮箱正则长达数百字符，实际项目几乎不用——**够用 + 可读**优先，精确校验交给"发验证码"环节。
:::

### 密码强度：必须有数字、字母，长度 8~16

```js
const pwdRe = /^(?=.*\d)(?=.*[a-zA-Z])[\w]{8,16}$/
// (?=.*\d)      前瞻：某处存在数字
// (?=.*[a-zA-Z]) 前瞻：某处存在字母
// [\w]{8,16}    主体：8~16 个单词字符
pwdRe.test('abc12345')  // true
pwdRe.test('abcdefgh')  // false —— 无数字
```

这是**断言实战**的代表：用前瞻条件叠加"与"逻辑，而不消耗字符。

## 4.2 提取类：捕获组 + 全局标志

### 提取所有数字

```js
'订单A1024，金额 88.5 元，折扣 9 折'.match(/\d+(\.\d+)?/g)
// ['1024', '88.5', '9']
```

### 提取 URL 参数

```js
const url = 'https://example.com/search?q=vue&page=2'
const params = {}
for (const m of url.matchAll(/[?&](\w+)=([^&]+)/g)) {
  params[m[1]] = m[2]
}
// { q: 'vue', page: '2' }
```

`matchAll`（需 `g` 标志）返回迭代器，每项含分组捕获，比多次 `match` 更清晰。

### 提取日期三段

```js
const [_, y, m, d] = '2024-01-15'.match(/(\d{4})-(\d{2})-(\d{2})/)
// y='2024' m='01' d='15'
```

## 4.3 替换类：分组引用改造文本

### 日期格式转换

```js
'2024-01-15'.replace(/(\d{4})-(\d{2})-(\d{2})/, '$3/$2/$1')
// '15/01/2024'
```

### 驼峰 ↔ 下划线

```js
// 驼峰转下划线
'userName'.replace(/[A-Z]/g, m => '_' + m.toLowerCase())
// 'user_name'

// 下划线转驼峰
'user_name'.replace(/_([a-z])/g, (_, c) => c.toUpperCase())
// 'userName'
```

替换函数 + 分组引用的组合，是批量改造文本的万能模板。

### 隐藏手机号中间四位

```js
'13812345678'.replace(/^(\d{3})\d{4}(\d{4})$/, '$1****$2')
// '138****5678'
```

## 4.4 清理类

### 去除多余空白

```js
'  hello   world  '.trim().replace(/\s+/g, ' ')
// 'hello world' —— 连续空白压成单个空格
```

### 千分位格式化

```js
'1234567.89'.replace(/\B(?=(\d{3})+(?!\d))/g, ',')
// '1,234,567.89' —— 经典前瞻应用，建议理解思路后收藏
```

## 4.5 何时不要用正则

::: warning 正则不是银弹

1. **解析嵌套结构**（HTML/JSON）：正则做不到任意深度嵌套，用真正的解析器
2. **复杂状态判断**：逻辑超过三四行的匹配，写成普通函数更可读
3. **性能敏感的热路径**：复杂回溯正则可能引发性能问题（甚至 ReDoS 攻击）

判断标准：一行正则能讲清楚 → 用正则；讲不清楚 → 写代码。
:::

## 本章小结

- 校验公式 `^...$`；手机号/邮箱/密码三套模板直接复用
- 提取用 match/matchAll + 分组；替换用分组引用 `$1`
- 断言叠加条件不消耗字符（密码强度场景）
- 嵌套解析、复杂逻辑别用正则——可读性优先
